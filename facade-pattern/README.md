# 外观模式

> 外观模式（Facade Pattern）是一种**结构型**设计模式。

## 作用

为复杂的子系统提供一个简化的统一接口，让客户端使用起来更方便。

## 场景

> 需要**将复杂的内部实现隐藏起来**，为客户端提供简洁易用的接口。

1. API 网关和服务聚合：通过 API 网关提供统一入口，前端只需调用一个接口就能获取聚合后的数据。
2. 降低耦合度：客户端不直接依赖具体子系统
3. 更好的层次结构：系统分层更清晰

## 实现

1. 提供简化的接口，封装了对子系统的访问；
2. 实现具体功能的多个类，它们相互协作完成复杂任务；
3. 通过外观类访问子系统功能。

## 优点

1. 简化接口：提供一个更高层次、更简单的接口
2. 解耦：将客户端与子系统解耦
3. 封装：隐藏子系统的复杂性

## 一句话总结

外观模式是“封装思想”的体现，用在中大型系统中像是一个贴心的“接待员”，帮客户处理背后的麻烦事。
