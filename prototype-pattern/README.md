# 原型模式

> 原型模式（Prototype Pattern）是一种**创建型**设计模式。

## 作用

解决某些场景下对象创建的成本问题，同时提供灵活性和动态性。

## 场景

> 复杂对象创建成本高，频繁创建相似对象。

1. 游戏开发：生成大量相似敌人或道具。
2. 配置管理：配置对象的复制，避免重复初始化。
3. 运行时决定对象类型：图形编辑器中复制图形元素，动态生成对象。

## 实现

> 通过复制一个已有的对象（原型）来创建新对象 ，而不是通过实例化类来创建。

1. 对象需要提供一个“克隆”自己的方法，如 `clone()` 。
2. 其它代码通过调用这个方法来创建新对象。

## 优缺点

### 优点

1. 避免重复初始化耗时操作。
2. 动态性高。
3. 隐藏创建细节，尤其是当构造复杂时。

### 缺点

1. 深拷贝实现复杂：若对象包含引用类型对象，浅拷贝会导致副本与原型共享引用，可能引发意外修改。需手动实现深拷贝，增加代码复杂度。
2. 违反封装原则：克隆直接复制字段值，可能跳过构造方法中的合法性校验，导致对象状态不一致。

## FAQ

### 1. 浅拷贝和深拷贝的区别

- 浅拷贝：**只复制基本类型**，引用类型只是复制了引用地址。
  - 注：`String` 虽然是引用类型，但它是不可变类，所以对原型的 `String` 内容进行修改，并不会影响副本内容。
    因为修改的是这个引用变量的指向（一个字符串），而不是修改底层字符串内容。
- 深拷贝：递归**复制所有层级的数据**，确保完全独立。

| 特性       | 浅拷贝             | 深拷贝         |
|----------|-----------------|-------------|
| 是否复制引用字段 | 否，仅复制引用地址       | 是，复制整个对象链   |
| 对象是否独立   | 否               | 是           |
| 修改是否互相影响 | 是               | 否           |
| 实现复杂度    | 简单              | 较复杂         |
| 性能       | 快               | 相对慢         |
| 内存占用     | 少               | 多           |
| 推荐使用场景   | 临时复制、不涉及引用修改时使用 | 需要对象完全独立时使用 |

### 2. 在原型模式中，是浅拷贝还是深拷贝？

原型模式本身不指定是浅拷贝还是深拷贝，它是一种“复制已有对象”的思想；

具体是浅拷贝还是深拷贝，**取决于你如何实现克隆逻辑**。

### 3. 必须实现 JDK 自带的 Cloneable 接口吗？

不是必须的。可以通过其它方式实现“克隆”或“复制”，而不一定非要用 `Cloneable` 接口和 `clone()` 方法。

## 一句话总结

原型模式适用于对象创建开销大、需要频繁创建相似对象的场景，它提高了性能和灵活性，但也带来了深拷贝实现复杂、封装性差等问题。
