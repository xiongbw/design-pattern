# 桥接模式

> 桥接模式（Bridge Pattern）是一种**结构型**设计模式。

## 作用

将抽象部分与实现部分分离，使它们可以独立变化而不互相影响。

## 场景

> 当系统中**存在多个独立变化的维度**，且需要避免通过继承导致类爆炸时。

1. 多维度独立扩展：一个系统存在多个正交变化的维度（如抽象类型 × 实现方式），直接继承会导致类爆炸（M × N 个子类）。
    - 图形库：形状（圆形/方形） × 渲染方式（矢量/光栅）。
    - 支付系统：支付类型（信用卡/支付宝） × 支付渠道（国内/国际）。
2. 跨平台/跨环境适配：同一功能在不同平台或环境下有不同实现，但需保持抽象接口一致。
    - 同一 SQL 接口运行时切换 MySQL / Oracle。
    - 统一接口，不同平台 iOS / Android 具体实现。
3. 共享底层实现：多个抽象对象需共享同一实现，且实现可能变化。
    - 多个窗口共享同一主题，主题可热更新。
    - 不同角色共用同一套装备系统。

## 核心角色

- 抽象类（Abstraction）：定义抽象接口，维护一个对实现部分的引用（即“桥”）。
- 扩展抽象类（Refined Abstraction）：对抽象部分的扩展，提供更精细的控制逻辑。
- 实现接口（Implementor）：定义实现部分的接口，供抽象类使用。
- 具体实现类（Concrete Implementor）：实现接口的具体行为。

## 实现

> 通过**组合代替继承**，使两者能独立变化。

1. 定义抽象类；
2. 定义实现接口；
3. 扩展抽象类；
4. 实现具体实现类；
5. 组合抽象类和实现类。

## 优缺点

### 优点

1. **分离抽象与实现**，便于独立扩展。
2. 避免多层继承，减少子类数量。
3. 符合**开闭原则**（新增维度时只需添加新类，无需修改现有代码）。
4. 避免类爆炸，提高扩展性

### 缺点

1. 复杂度增加：增加系统复杂度，理解成本稍高。

## 一句话总结

通过组合将“是什么”（抽象）和“怎么做”（实现）解耦，使两者能独立变化。
